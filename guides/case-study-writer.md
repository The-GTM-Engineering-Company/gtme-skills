# Client Case Study Writer

Turn an engagement’s approved evidence into useful case studies for different buyers. Create founder, sales, marketing, operations, or company-wide editions, with named and anonymized options. Each factual claim is checked against a private source map.

**Public skill package:** [Client Case Study Writer](https://github.com/The-GTM-Engineering-Company/gtme-skills/tree/main/skills/case-study-writer)

No GitHub account, invitation, or username sharing is needed to download the package. Each operator still needs their own authorized access to the relevant services.

## 1. Before you start

- A local assistant and a private workspace for source material and drafts.
- Approved engagement evidence: delivered artifacts, before/after measurements, recaps, handoff material, and relevant quotes or transcripts.
- The requested reader editions, brand/style, and whether client names and results may be shared.
- Optional: a Notion connection and the exact parent page when publishing is requested.

## 2. Set up with your assistant

Open a private client workspace and paste:

```text
Install the case-study-writer skill from:
https://github.com/The-GTM-Engineering-Company/gtme-skills

Read skills/case-study-writer/SKILL.md and its references. Use my
approved engagement sources and keep the fact-source map private.
Confirm the reader editions, brand, named/anonymized scope, and any
missing evidence. Start with drafts; do not publish or send them yet.
```

Keep the complete skill folder and its reference files together. Your assistant can install it for Codex or Claude Code, or read it directly from the downloaded repository.

## 3. Run the first scoped task

```text
Create the requested case-study editions from this engagement.
Trace every metric and quote to a source. Distinguish delivered
capabilities from measured business results, and keep shared facts
consistent across versions. Flag missing evidence instead of inventing
results. Check anonymized versions for identifying details and links.
```

## 4. What you should receive

- The requested case-study drafts, each written for its intended reader.
- A private fact-source map for metrics, quotes, completion claims, and unresolved evidence.
- A short review list covering disclosure, missing information, and any needed corrections.

See the [synthetic example](https://github.com/The-GTM-Engineering-Company/gtme-skills/blob/main/skills/case-study-writer/examples/brief.md) for the expected shape. It contains invented data.

## 5. Review and continue

Review the facts and permission to disclose client names, quotes, and results. Anonymization does not make confidential information shareable automatically. If publishing to Notion, provide the exact destination and ask the assistant to publish the approved editions and verify each page.

## Practical limits

No source evidence means no supported metric or testimonial. Notion is optional; drafts can remain local. The package includes a GTME style default that can be replaced with the client’s own style.
