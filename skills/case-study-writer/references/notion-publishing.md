# Publishing case studies to Notion

Use the exact destination supplied or approved by the operator. There is no default workspace or Case Studies hub ID in this package. If no destination is known, deliver local drafts.

1. Fetch the target page and inspect current child pages and content. For revisions, find the existing edition rather than creating a duplicate.
2. Read the current Notion tool schema and enhanced Markdown specification. Create new editions as child pages of the chosen parent only when requested.
3. Use an edition-specific title and optional icon; avoid repeating the full page title as the first content heading.
4. For revisions, use the smallest supported content edit. Preserve child-page blocks, unrelated SOPs, comments, and layout. Do not replace a parent page simply to add an edition.
5. Fetch each written page and the parent. Verify complete content, metrics, edition labels, links, and placement. Report actual URLs and any unsuccessful writes.

Keep fact-source maps, confidential evidence, and internal notes outside the shareable pages. Page creation does not imply public internet access. Use the intended recipient's sharing permissions; do not broaden parent-workspace access as a side effect.

No source system is modified and no client message is sent as part of publishing a case study unless the user separately requests it.
