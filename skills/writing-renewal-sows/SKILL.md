# SOW Completion Audit & Renewal Scope

Audit first, then scope the next period. Recaps and trackers are useful evidence, but neither is automatically authoritative: later corrections, live artifacts, and client acceptance can change the status.

## Configure

Resolve the previous scope, approved evidence corpus, excluded commercial/private sections, private output location, current engagement date, renewal term/priorities, and requested document destination. No specific task tool or document provider is required. Ask only for missing decisions that affect the scope.

Keep fee/payment/rate/signature sections separate from the authored delivery scope. Do not copy those commercial details into repository files or shared audit outputs. If a source mixes them with scope, use an operator-supplied scope extract or a tool/view that limits extraction to the needed sections. Preserve commercial sections in any target document.

## Audit

1. Expand the old SOW into individual deliverable bullets with stable IDs. This is the unit of audit; a completed phase title does not prove every bullet is complete.
2. Read the underlying artifacts, recaps, commitments, approved messages, and relevant calls. Use [the audit method](references/audit-method.md) to verify claims, hunt for later reversals, and find work outside the original scope.
3. Assign evidence-backed statuses: DELIVERED, PARTIAL, IN FLIGHT, NOT REACHED, SUPERSEDED, or UNVERIFIED when source coverage prevents a conclusion. Missing access is not proof of non-delivery.
4. Deduplicate additional work and distinguish it from an already-counted contractual deliverable. Record deferred promises, missing documentation, and remaining decisions.
5. Deliver the completion audit and carryover register. Update an existing tracker only when that write is in scope; preserve its structure and link each changed status to evidence.

## Draft the renewal

Use [the output template](references/output-template.md). Explain the starting situation, what is now evidenced, and the next business priorities. Combine confirmed carryover with new scope; explicitly restate or drop superseded items. Make recurring support/reactive work visible when the operator wants it in scope.

Respect the requested term, assumptions, ownership, and deliverable limits. Do not invent commercial terms, legal clauses, dates, resources, or client commitments. Leave unresolved choices clearly marked for the operator in the private draft.

## Deliver

Keep audit, evidence map, and draft in the private workspace. Share an accurate summary of delivery status and renewal decisions. Publish to the specified document only when requested, preserve commercial/signature content, and read back the result. Task creation, client messages, contract execution, and billing changes are separate actions requiring their own scope.

See [the synthetic example](examples/audit.md). This skill supports drafting and delivery analysis; contract review remains the operator's responsibility.
